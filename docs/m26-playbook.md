## 2 分类详解 + 最短示例

### §1 错误优先守卫 [证据]

- 现象：ROM 用 bnez a0 把成功路径甩到远端、失败块紧跟；写成「先判非空、成功就 return」会得到 beqz，逐词差 11 词。
- 写法：空指针/错误分支在前并提前 return，成功路径做函数最后一句。

      if (p == 0) { FUN_001cf618(D_00266480); return 0; }
      return *(signed char *)(p + 0x72);

- 命中：0x001B8F30、0x001B7D78、0x001B7E90、0x001B89D0（return -1）、0x001B8C80、0x001B8D58、0x001C4098、0x001C4100、0x001AECD0 —— 均 1–2 次命中 [证据]
- 反例：0x001B8AA8 反向写法（if (p) return ...; F(); return -1;）差 11 词 [证据]

### §2 绝对地址实参写 extern 符号 [证据]

- 现象：目标 lui 0x1B8 + addiu -0x1B10 是标准 %hi/%lo 进位；裸常量 0x1B7E4F0 给 lui 0x1B7 + addiu +0xE4F0，差 2 词。
- 写法：为绝对地址声明数组符号（char 型即可），实参传符号名。

      extern char D_001B7E4F0[];      /* 符号名里的地址必须与真址逐位一致 */
      FUN_00205dd0(D_001B7E4F0);      /* 不要写 (void *)0x1B7E4F0 */

- 命中：0x00112878（换符号后一次命中）、0x001B2140、0x001AECD0（56/48 双尾声 → 44/44）、0x001B7D78、0x001B7E90、0x001B89D0、0x001B8F30 [证据]
- 坑：符号名少一位就整体错（0x001AECD0 的 brief 把 0x002656C0 写成 0x265C0，会生成 lui 0x0002 vs 目标 0x0026）。

### §3 三段式「调用-调用-尾调」 [证据]

- 现象：两条 jal + 末条 j（sibcall）。
- 写法：三条顺序写，末条一定裸写；返回值没人用时前两条包不包 do{}while(0) 都出 jal。

      FUN_001ce9b8();  FUN_001b8f90(p);  FUN_001ce9c0();   /* jal / jal / j */

- 命中：0x001B03D8、0x001B4768、0x001B6330、0x001B8F60、0x001B90E8、0x001B8A00、0x001B4A60、0x001B4AF8、0x001B9A10、0x001BB5F8 [证据]
- 需要跨调用保参的变体：s0 = a0; do { F1(); F2(s0); } while (0); F3();（0x001AFFA0、0x001B80D8、0x001B82A8、0x001C3A50、0x001C3D98、0x001C3E08、0x001C3EA0）[证据]
- 反例：0x001B44E0 把末条也包了 do-while，j 变 jal [证据]；首条无参调用要按 void 原型写，带参会多一条 move（0x001B6330）[证据]

### §4 双尾调 [证据]

- 现象：两条 return 路径在 ROM 里都是 j（含错误分支）。
- 写法：两条都写成 return F(...)，函数声明 int 直接透传返回值。

      if (p == 0) return FUN_001cf618(D_00266510);
      return FUN_001b3c38(*(int *)(p + 4));

- 命中：0x001B95E0、0x001B99E0 [证据]
- 单侧变体：0x001C4670 空指针分支尾调 + return;，非空分支只存一字节（函数 void）[证据]

### §5 重复返回块写 if/else-if/else [证据]

- 现象：ROM 有两个完全相同的 D = 0x8001; return 块；写成两个提前 return 会被 GCC 合并成共享块，少 8 字节（40/48）。
- 写法：单出口三分支。

      if (a0 == 0) D = 0x8001;
      else if (a0 == 1) D = a0;
      else D = 0x8001;

- 命中：0x001C3748（第 1 次提前 return 40/48，第 2 次三分支 48/48）[证据]

### §6 一个符号里两个函数 [证据]

- 现象：splat 把两个相邻小函数切进一个符号，片段里两个 jr ra / 两个 j，单个 C 函数不可能产生。
- 写法：两个函数都写进同一个 .c，各自用自己的符号名与真实 callee，管线按符号区间比较。

      void FUN_001b2790(void) { FUN_A(); }   /* 前半 20B：j FUN_A */
      void FUN_001b27a8(void) { FUN_B(); }   /* 后半 20B：j FUN_B */

- 命中：0x001B2790（+0x001B27A8，44 字节区间 ndiff=0）、0x001465A0（+0x001465B8 两个 thunk）、0x00130FB0（setter + 0x00130FC8 getter 配对）[证据]
- 可推广性：队列里 size==8 的条目只剩 1 个 → 个案手法，不进批量配方 [证据]

### §7 同一字段两次使用分别重新读 [证据]

- 现象：目标对同一字段有两次 lw，第二次落在第一次调用之后。
- 写法：两处各自写完整表达式，别缓存进局部。

      FUN_001cc5b0(*(int *)(p + 4));
      FUN_001cc358(*(int *)(p + 4));

- 命中：0x001B2CC8 [证据]
- 反向：0x0011ABC8 目标就是 lw/addiu/sw 顺序时，要把 *(int *)(p + 0x44) 读进局部 q 再用（q[2] += 8 形式）[证据]

### §8 字段类型精确 [证据]

- 现象：lb 写成 lbu 差 1 词；第二参声明成 char 会多 sll/sra 符号扩展（56/48）。
- 写法：lb → signed char、lbu → unsigned char；存 char 字段时形参用 int + (char)v。

      void f(char *p, int v) { *(char *)(p + 0x70) = (char)v; }   /* 不是 char v */
      int  g(char *p) { return *(signed char *)(p + 0x72); }      /* lb，不是 lbu */

- 命中：0x001B8F30（signed char）、0x001B8CF0（char v 56/48 → int+(char)v 48/48）、0x001C4670、0x001C4098（signed char）/ 0x001C4100（int）[证据]

### §9 7 参函数走扩展寄存器 [证据]

- 现象：jal 前 8 条内出现 daddu v0,a3 / t1=t0 / t0=v0 / a3,sp / t2,sp+4 —— callee 吃 a0–a3 + t0–t2。
- 写法：原型照 disasm 写 7 个参数，局部开 char buf[16]，第 4 参传 buf、第 7 参传 buf+4。

      char buf[16];
      FUN_7(a0, a1, a2, buf, a3v, a4v, buf + 4);

- 命中：0x001AF190（一次命中，44/44）[证据]
- 适用条件：target 在 jal 前 8 条内写 $t0–$t3；48B 同族多见此形态，属可推广手法（t277）[证据]

### §10 core vs size [证据]

- 现象：queue 记 size=48，实际有效码 44，末尾 4 字节是 padding；按 48 提交会多一条。
- 写法：一律按 queue 的 core 字段对齐与提交，不要用 size 硬凑。
- 命中：t259 四只、t269 四只、t272 五只、t274 五只、t276 五只 —— 全部 44/44 [证据]

### §11 跳转表 [证据]

- 现象：asm 里 lui/addiu 一对指向带 jtbl_ 前缀的表。
- 写法：python tools/jtbl.py --va <表址> --count <条数> 先解表；switch 里每个 case 都列（含空 case: case 3: break;）、每 case return 表项、并在 jtbl-map 登记。
- 命中/依据：0x00167568（idx3/4/5/9 是空 case，必须显式列）、0x001C1F10（case 源序 1,2,4,5,6,7,8→9→3→0 决定块布局）、0x0019E4A8（21 项表，case 源序 2,1,0,…,20,19；返回类型必须 int，void 会把临时寄存器整体下移一格）[证据]
- 表项陷阱：0x0015B320 的 6 项表里 [6][7] 是 0 padding、[8][9] 属别的数据 —— 只取真实条数 [证据]
- 完整铁律（表址小端映射、%hi 偏置用 addiu、近失切 /opt/ee29）见 build/m26-subsystems/jtbl-playbook.md
- 0x0019E4A8 / 0x00143B78 的 B2 复验仍在进行（t283），结论以该任务为准。

### §12 -G8 / gp 相对 [证据]

- 现象：全局访问是 lw v0,-28060(gp) 形态，不是 lui/addiu 两段。
- 写法：该 TU 用 -G8（queue cls=needs_G8）；gp 偏移按符号名反推，别凭手感。
- 命中：0x00123750（g=8，36/36；第 1 次把 gp-0x6D40 写成 gp-0x6DFC 只差 1 词，第 2 次命中）[证据]
- needs_G8 地址要做 -G 扫描（g=0/8 各一遍，如 0x00143B78）

### §13 骨架 A：夹心三连（首末两层钩子 + 中间返回值落局部） [证据]

- 现象：ROM 是三条普通 jal（钩子A / 中层 / 钩子B），末层**不是**尾调；若把中层写成 `return MID(p);`，GCC 会把中层变 sibcall（`j`），后两条 jal 全错。
- 写法：

      int f(char *p) { int r; FUN_001ce9b8(); r = MID(p); FUN_001ce9c0(); return r; }

  三条要点：① 中层返回值必须落局部 `r`，不能直接 return；② 函数以 `return r` 收尾，因此末层钩子保持普通 `jal`；③ 首层/末层按 ROM 决定带不带 a0 —— 本轮两族都是无参（`FUN_001ce9b8`/`FUN_001ce9c0` 与 `FUN_001c46a0`/`FUN_001c46a8`），p 由 `$s0` 跨调用保存。
- 命中：0x001B92A8、0x001B9408、0x001B94B0、0x001B9520（中层 0x1B92E0/0x1B9440/0x1B94E8/0x1B9558）；0x001B9A58、0x001B9B48、0x001C3910、0x001C4060（首末换 0x1C46A0/0x1C46A8）—— **8 只全部首轮 1 次命中** [证据]
- 反例：中层写成 `return MID(p)` 时末条变 `j`，与 §3「末条不包 do-while」是两个不同方向，先看 ROM 末条是 `jal` 还是 `j`。

### §14 骨架 B：首层换成带 a0 的 FUN_001b5c70(p) [证据]

- 现象：同样是三连，但首层吃 a0、末层是 `FUN_001b5c88()`（无参），且函数**无返回值** —— 所以末层是尾调 `j`。
- 写法：

      FUN_001b5c70(p); FUN_001b4a90(p); FUN_001b5c88();   /* jal / jal / j */

  末层不要再包 do-while（包了就变 `jal`，见 §3）。
- 命中：0x001B4A60、0x001B4AF8、0x001B4768、0x001B5340、0x001B53E8、0x001B6330 —— 全部首轮命中 [证据]
- 与 §13 的分界：**末层是 `FUN_001ce9c0()`/`FUN_001c46a8()` 且函数有返回值 → §13（末层 jal）；末层是 `FUN_001b5c88()` 且函数 void → §14（真尾调）**。先看 ROM 末条指令，再选骨架。

### §15 守卫型：错误优先 + extern 符号 + 尾调读字段（3/3 首轮） [证据]

- 现象：ROM 形态 `v0=a0; if (v0) goto 尾部; jal FUN(0, D_XXXX); return 0;` —— 空指针走**错误分支**，调一条告警函数并返回 0；非零分支读字段后尾调/直接返回。
- 写法：

      extern char D_00267B88[];
      if (a0 == 0) { FUN_001c0340(0, D_00267B88); return 0; }
      return *(int *)(a0 + 0xC);

  三件套缺一不可：错误分支在前（§1）、绝对地址传 `extern char D_XXXX[]` 符号名（§2）、非零分支写成 `return *(int *)(a0 + off)`。
- 命中：0x001C09F0（D_00267B88 / +0xC）、0x001C2670（D_00268090 / +0x1C）、0x001C5188（D_00268860 / +0x10）—— **3/3 各首轮 1 次命中** [证据]
- 变体：告警函数的首参可以是 p 本身 —— 0x001C53D0 / 0x001C5488（t340）写成 `FUN_001c4cf8(p, D_00268900)` 同样一次命中 [证据]

### §16 位域读取要用无符号移位 [证据]

- 现象：目标 `lw v0,(p); srl v0,v0,8; andi v0,1`；写 `*(int*)p >> 8 & 1` 得 `sra`，差 1 词。
- 写法：

      return (*(unsigned int *)p >> 8) & 1;   /* 必须 unsigned 才出 srl */

- 命中：0x001E2390（`if (a1 == 1) return (*(unsigned int*)p >> 8) & 1; FUN_001e1c68(); return 0;`，第 3 次改 unsigned 才过）[证据]
- 推广：ROM 里凡是 `srl`/`srlv` 的取位、掩码、位域运算，C 侧都用 unsigned 表达；`sra` 才保持有符号。

### §17 只有两条调用时，第二条要包 do-while 才是 jal [证据]

- 现象：`F1(); F2(...);` 直接写在函数末尾 → GCC 把 F2 折成 sibcall（`j`），长度少 4 字节。
- 写法：

      FUN_001ab4b0(); do { FUN_001ac540(D_00860FC0, D_00861000, 100); } while (0);

- 命中：0x001AC048（第 2 次，第三参 100）、0x001AC0C0（同形，第三参 102）[证据]
- 旁证：0x001F6080、0x001F6118（t340）包了 do-while 后长度回到 52/56，只剩 2 词调度差 [证据]
- 与 §3 / §14 合并成一条判据：**ROM 末条是 `jal` 就包、是 `j` 就不包**，不要按「几条调用」背规则。

### §18 符号地址与常量偏移必须分离（别折进 addiu） [证据]

- 现象：写 `*(int *)(D_01B9F8F0 + 0x14)` 时 GCC 把 +0x14 折进符号（`addiu r,%lo(D_01B9F8F0+0x14)`，形如 `addiu 0x904`），与 ROM 的 `lui 0x1BA + addiu -0x710` 差 1–2 词。
- 写法：

      char *p = D_01B9F8F0;      /* 先把符号落成基址寄存器 */
      *(int *)(p + 0x14) = a2;   /* 再按偏移存 */
      *(int *)(p) = a0;
      *(int *)(p + 0x10) = a1;

- 命中：0x0019C208（56 B，第 3 次；分离后 `lui 0x1BA + addiu -0x710` 对上，剩 3 词差在三条 store 次序：ROM 是 0x14、0x0、jal 延迟槽 0x10）[证据]
- 同坑旁证：0x00102190 必须写 `char *p = D_A94700;`，否则 %lo 进位把 `lui 0xA9` 变 0xAA [证据]
- 与 §2 分工：§2 管「绝对地址作**实参**」，本条管「符号 + 常量作**访问基址**」。

### §19 同一字段两次使用：分别重读还是落局部，按 ROM 的 lw 条数定 [证据]

- 现象：少数函数要两次 `lw` 同一字段（第二次在中间调用之后），多数只读一次；写反了差 1 条指令。
- 正例（ROM 两条 lw）：

      FUN_001cc5b0(*(int *)(p + 4));
      FUN_001cc358(*(int *)(p + 4));   /* 第二次重新读 */

  命中 0x001B2CC8（44/44、首轮）[证据]
- 反例（ROM 一条 lw）：0x0011ABC8 必须 `int q = *(int *)(p + 0x44); *(int *)(q + 8) += 8;` 落局部后用两次，写两遍反而多一条 lw [证据]
- 判据：先在 ROM 里数同字段 `lw` 的条数与位置，再决定写法 —— 这条不能背结论。

### §20 三类不要派 cracker（不可达 / 工具链墙） [证据]

| 类 | ROM 现象 | 判定 | 案例 |
| --- | --- | --- | --- |
| movn 条件选择 | `v1 = a0 ^ 0x5C; v0 = 0x2F; movn v0,at,v1` —— 异或结果当条件做无分支选择 | C 层 `?:` 会生成分支，无法触发此形态 | 0x001C1058（3 次未过，t331） |
| 需 volatile 重读 | 写完计数器后用**同一基址再 lw 一次**做比较；普通 -O2 会 CSE 成一条 load | volatile 被 sanitizer 禁止 → 优化墙 | 0x001CE958（40/44、11 词、6 种写法无效）、0x001CE928（11 词） |
| splat 边界零填充段 | 函数体之后到下一符号**全是零字节**，末尾一条 `b` 回跳 | 不是 C 代码，是数据/对齐段 | 0x001B2758（core 56、3 次未过） |

- 处置：这三类直接在 queue 标 skip，别花 check-one 预算。
- movn 的例外：**三元式能触发 movn** —— `return i != 4 ? i : -1;` 在 0x00102130 正常出 `movn`（t9）[证据]。所以先看 ROM 的 movn 是「三元/clamp」还是「异或+常量选择」，前者可写、后者不派。

### §21 「lw v0/v1 互换」不是寄存器分工墙，而是把中间指针缓存进了局部量 [证据]

- 现象：**长度精确对齐**（76/76、80/80），唯一差异是某条 `lw` 的目标寄存器 v0↔v1 互换，其余全同。典型 first diff：word 5 `8c420008 (lw v0,8(v0))` vs 目标 `8c430008 (lw v1,8(v0))`。
- 根因：把 `*(int **)(p + 0x44)` 缓存进具名局部 `q` 后，gcc 的活跃区间变了，把第一段链的缓冲指针放进 v0；ROM 是每处重新读、指针留在 v1。**这不是分配自由度不够，是源码形态不同。**
- 写法（整段照抄，只换 callee）：

      int f(char *p)
      {
          unsigned char *b = (unsigned char *)*(int **)((char *)*(int **)(p + 0x44) + 8);
          CALLEE(b[1]);                 /* 两参形态：CALLEE(b[1], b[2]) */
          *(int *)((char *)*(int **)(p + 0x44) + 8) =
              *(int *)((char *)*(int **)(p + 0x44) + 8) + 4;
          FUN_00117dc0(p);
          return 0;
      }

  两条硬约束：① 中间指针**全部展开成内联表达式**，两处各自重读 `*(int **)(p + 0x44)`；② 指针加法必须 `(char *)` 之后再 `+8` —— 直接对 `int *` 写 `+8` 会被放大成 32 字节偏移（t395 踩过一次）。
- 命中（改前 → 改后）：0x0011AA88、0x0011AAD8、0x0011B2C8、0x0011C6E0、0x0011C730 —— t394 的缓存写法 0/5、各差 6–7 词；t398 改成内联写法后 **5/5 一次命中** [证据]
- 同族第二批（t395 直接按此写法 5/5 命中）：0x0011C780、0x0011C7D0、0x0011C900（第二参是 `*(unsigned short *)(b + 2)`，即 `lhu`）、0x0011CBC8、0x0011CF30 [证据]
- 反向旁证（同一机制，但**哪一段缓存要看 ROM**）：t392 的五只（0x0011A720 / 0x0011A770 / 0x0011A868 / 0x0011A8B8 / 0x0011AA38）里，**第一段的 `r` 载入必须是单条嵌套表达式**（q 留 v0、r 进 v1 才对），而**第二段反而要保留具名 `q`** —— ROM 是 `lw v1,68(s0); move a0,s0; lw v0,8(v1); addiu v0,v0,N; jal; sw v0,8(v1)`。判据：**看 ROM 同一基址在两次使用之间有没有重新 `lw` 基址**。
- 与 §19 的分工：§19 数「同一字段被读几次」，§21 管「中间指针要不要落局部」；两者同属「内联 vs 具名」一族，下笔前先数 ROM 的 `lw` 条数与基址复用情况。

#### §21b 同类假墙的两条岔路：先数实参，再判墙

| 假墙类 | 症状 | 判定方法 | 案例 |
| --- | --- | --- | --- |
| A 缓存局部量（§21 主体） | 长度精确、v0↔v1 互换、源码里有具名中间指针 | 展开成内联重读，一处一读 | 0x0011AA88 族（t394 → t398，5/5） |
| B 少传实参 | **callee-saved 分工与 ROM 相反**（s0/s1 对调）、差 3–4 词 | 数 ROM 每个调用点 `jal` 前 3 条对 a0/a1 的写入，与 callee 原型参数个数比对 | 0x001B49D0 / 0x001AEF38 / 0x001AF490 / 0x001B4868（t386，4/4） |
| C 真墙（volatile / CSE 等） | 长度对、实参齐、内联也不行 | 排除 A/B 之后才判 C，C 类归 §20 | t387 复查 42 例 fixable=0；0x002034F0 需 volatile |

- B 类机制（t386）：写成 `FUN_FIRST(a0)` 时 gcc 只需为 a1 保一个跨调用寄存器，于是把 **s0 分给 a1**；补成 `FUN_FIRST(a0, a1)` 后两个参数都要跨调用保活，gcc 就给出 **s0=a0 / s1=a1**，与 ROM 一致，4 词差一次消失 [证据]
- 但**不是参数越多越好**：0x001AD9C8 的正确形态就是 `FUN_001af7d0()` 无参（t392 恢复后 MATCH g=0）[证据] —— 判据始终是「ROM 的 `jal` 前到底写了几条 a0/a1」，不是「callee 原型几个参数就传几个」。
- 排查顺序：遇到「长度精确 + 3–7 词差」按 **A → B → C** 走；A 最便宜（只改源码形态，不动编译选项）。
- 待澄清：t387 曾把 42 例（含 0x00115B20 / 0x00115D38 的 `srl/addu/lbu` v0/v1 互换）判为 wall，而 t398 证明 v0/v1 互换可修 —— verifier2 正按 §21 重算这 42 例（t400），**结论以 t400 为准**；在那之前，凡「v0/v1 互换」先按 §21 复验再登记。

### §22 有类型指针 + 字节偏移 = 指针算术陷阱 [证据]

- 现象：长度精确对齐，唯一差异是某条 `lw` 的**立即数被放大 4 倍** —— got `lw a1,0x30(a0)` vs want `lw a1,0xC(a0)`，每只各差 1 词。
- 根因：`q` 声明成 `int *`，却写 `*(int *)(q + 0xC)` —— C 的指针算术先把 0xC 乘 4 得 0x30；目标要的是**字节位移 0xC**。
- 写法（二选一，下标最稳）：

      int *q = *(int **)(p + 0x44);
      FUN_00180a68(q, q[3], 0, 0, 0);          /* 对：q[3] == 字节偏移 0xC */
      /* 错：FUN_00180a68(q, *(int *)(q + 0xC), ...)  → 立即数变 0x30 */

  另一种等价写法：`*(int *)((char *)q + 0xC)`（显式字节指针，编译结果一致）。
- 命中：0x00180C60 / 0x00180CA8 / 0x00180CF0 / 0x00180D38 / 0x00180D80 —— 第一版写 `*(int *)(q + 0xC)` 时五只各差 1 词，改成 `q[3]` 后 **5/5 一次命中**（第二轮尝试）[证据]
- 判别：ROM 立即数 = C 里写的偏移 × 4 → 就是这条；反过来若 ROM 立即数正好是 `0x30`，说明原码确实写的是 `q + 0xC`（原码自己就这么写），那就照写 —— 以 ROM 的立即数为准，不要一味改下标 [推测]
- 与 §18 的分工：§18 是「**符号地址** + 偏移被折进 addiu」（错 ±0x8000 进位）；§22 是「**有类型指针** + 偏移被乘元素大小」（错 ×4）。两者都让立即数出错，但错法与修法都不同。
- 与 §21 的区分：§21 差的是**寄存器号**（v0↔v1）；§22 差的是**立即数**（0x30 vs 0xC）。

### §23 全局声明方式决定访问形态：要 gp 相对声明 int，要绝对寻址声明 char 数组 [证据]

- 现象：目标用 `sw vN,-off(gp)`（gp 相对、1 条指令）；我们出 `lui vN,%hi(D_x) + sw vN,%lo(D_x)`（绝对两段）—— 或反过来：要大地址物化却给了 gp 相对。
- 机制：同一符号的两种形态由**声明方式 + TU 的 -G**共同决定：
  - `extern int D_x;`（标量，尺寸在 g 阈值内）→ 编译器可直接 gp 相对存取。
  - `extern char D_x[];` 且把**数组名当值用**（传实参、赋给指针）→ 必须先物化地址，只能 `lui + addiu`。
- 写法：要 gp 相对就声明标量；要绝对地址就声明 char 数组并传符号名。

      extern int  D_00270BD4;          /* → sw v0,-xxxx(gp) 形态 */
      extern char D_00267B88[];        /* → lui + addiu 物化地址 */

- 命中/依据：0x00157780 —— 把全局从 char 数组改成 `int` 后，目标用的 gp 相对 store 形态**才出现**（t442；该函数仍有 16 词 prologue/调度差，属另一类问题）[证据]；反方向 0x001C09F0 / 0x001C2670 / 0x001C5188 —— 需要 `lui+addiu` 绝对地址，用 `extern char D_xxxxxx[]` 传符号名才一次命中（§15）[证据]
- **「全局声明方式」三件套（+1 条禁令）适用条件**：

| 目标形态 | 声明方式 | 用法 | 章节/案例 |
| --- | --- | --- | --- |
| gp 相对 `sw vN,-xxxx(gp)` | `extern int D_x;`（标量） | 直接 `D_x = v;` / `v = D_x;` | §23 · 0x00157780、§12 的 0x00123750 |
| 绝对 `lui + addiu`（地址当值） | `extern char D_x[];` | 传数组名作实参 / 赋给指针 | §2 · 0x00112878、§15 · 0x001C09F0 族 |
| 绝对 + 常量偏移访问 | `char *p = D_x;` 再 `p[off]` | 先落基址寄存器，再按偏移访问 | §18 · 0x0019C208 |
| 裸常量 | **禁止** | 会破坏 %hi/%lo 进位 | §2 · 0x00112878 |

- 判据一句话：**看 ROM 那条访问是 1 条（gp）还是 2 条（lui+addiu）**；1 条要标量声明，2 条要数组名/地址物化。同一函数里两种形态可以并存 —— 按每个符号各自的目标形态分别声明。

### §24 空桩池（placeholder）转正 —— 当前命中率最高的一块 [证据]

- **什么是空桩**：`src/functions/<addr>.c` 只有占位注释或空函数体，编译出来 **8 字节 `jr ra`** —— 等于从没写过候选，却被记成"已尝试"。
- **池子有多大**（t508 实测 near-miss 池 301 条）：**62 条是空桩（20.6%）**，比上一轮多 9 条。分三类：
  - **C-able 44**：≤64B 有 7、65–96B 有 5、97–160B 有 5、>160B 有 27 → **这才是金矿**
  - no-body 15：`0x002055A0…0x002057E0` SDK 桩家族 14 只 + `0x00100008` crt0 1104B → 疑 asm-native
  - C-unreachable 3：`0x001DBDC0` / `0x00203604` / `0x00206620`
- **怎么找（一条判据）**：`compiled_len <= 8 && queue.size > 32` → 空桩；建议 near-miss 池生成器把这类标 `cls=stub`。
- **怎么做**（4 步，别删占位）：
  1. 反汇编确认真实内容（`asm/1000.s` 按 VA 取；有 jtbl 就 `tools/jtbl.py`）；
  2. **直接覆盖占位文件**（不要删 —— 保留"派过但没写"的审计线索）；
  3. `python tools/tu_batch.py prepare --addrs <地址…>` 按 queue 重写卡；
  4. check-one 验证。
- **高频形态**（t515 的 5 只命中样本，可直接照抄）：

| 形态 | 写法 | 命中 |
| --- | --- | --- |
| thin wrapper | `void f(void) { FUN_00105728(); }` | 0x00117668（两段 wrapper，1 次）、0x001B3C88（1 次） |
| memset 包装 | `FUN_001fbb84(D_01B74230, 0, 8332);` | 0x001016B8（2 次；第一次把 8332 写成 8340，差 1 词） |
| getter + 尾调 | `return FUN_001d1230(*(int *)a0);` | 0x001BC2F8（1 次） |
| setter 对 | `*(int *)(a0 + 0x2C) = a1; *(int *)(a0 + 0xC) = 1;` | 同上 |
| 三段式（§13/§14） | `FUN_001b5c70(a0,a1); r = FUN_001b4498(a0,a1); FUN_001b5c88(); return r;` | 0x001B4450（2 次；首层 callee 别猜，按 jal 换算） |

- **成绩**：**10 只 5 中（50%）** —— 其中 **3 只首轮 1 次就过**（0x00117668 / 0x001BC2F8 / 0x001B3C88），另 2 只第 2 次命中（0x001016B8 / 0x001B4450）。
  - 口径注记：t515 自述"4 只一轮过"，但它的表格只有 3 只 `attempts=1` —— **以表格为准**。
- **跳过条件**（这 5 只未过的原因，见到就别写）：
  - **mult/定点乘 + 表索引**：0x00107D88 / 0x00107CB8（`mult a0,0x4E280` 后取 lo 索引）→ 未写
  - **v0/v1 互换类**：0x0011CB28 / 0x0011CB78（76/76、6 词）→ 先按 §21 复验
  - **守卫链提前返回被合并**：0x001B3F30（96/88，多 8 字节）→ 属 §5 的 if/else 家族
  - 通用红线（沿用 §20）：movz/movn、lwl/lwr、bnel 填满延迟槽、帧 0x30 且 s0@0、mult 定点运算
- **判墙四步（本节的落点）**：① §21 内联复验 ② ee29 重编 ③ **检查是不是空桩/占位** ④ 再判墙。
  - ⚠️ 同步项：`docs/m26-walls.md` 行 6 的判墙铁律目前仍是**三步**（缺第 ③ 步）；本次按任务范围只改 playbook，需下一单补那一行。
- **收益**：清掉空桩不只是多命中 —— 池子里 20.6% 的"假未匹配"被清掉后，**匹配率分母也变真实**。

### §25 thin wrapper 族批量法 —— 今天 20/23（87%），最适合批量扫 [证据]

- **判定（asm 指纹，5 条）**：

      addiu sp, sp, -0x10
      sd    ra, 0x0(sp)
      ld    ra, 0x0(sp)
      j     FUN_x
      addiu sp, sp, 0x10

  看到 **`ld ra` 后紧跟 `j FUN`** 就是这一族（帧只为存/取 ra，纯 sibcall）。
- **写法**：`void f(void) { FUN_x(); }` —— GCC 生成与 ROM 完全一致的 sibcall，不需 do-while、不需任何修饰。
- **带参版**：`j` 前有 `move a0,...` / `lw a0,off(a0)` 时按实际搬运写形参：

      void f(int a0) { FUN_001c65e0(*(int *)(a0 + 0xC)); }   /* j 前 lw a0,0xC(a0) */

- **批量法（可交 optimizer 一键做）**：遍历 queue 里 `ins <= 7~8 且 calls >= 1` 的地址 → 反汇编看是否 `ld ra; j FUN` → 直接生成 `void FUN_<addr>(void){ FUN_<target>(); }`。
  - 按今天 71 个 tiny 候选的密度估算，**还能批量捡 30+ 只**（t537）。
  - **坑**：callee 要按 `j` 的 26 位目标精确换算 —— 0x00117270（差 1 词）与 0x001B25C0（差 3 词）都是换算算错后才修正的。
- **命中证据**（t537，8/11 = 73%）：0x00112600（→FUN_001ea668）、0x001171C8（→FUN_00105038）、0x00117270（→FUN_00105200）、0x001173D0（→FUN_00105390）、0x00117620（→FUN_00105660）、0x00117638、0x00117650（**两只指向同一 callee FUN_00105698**）、0x00142BD0（→FUN_0010c230）—— **八只全部一轮过**。
- **一符号四函数**：0x001B2518（96 B，四段）—— 前三段是 `{ FUN(); }`，第 4 段是 `lw a0,0xC(a0); j FUN_001c65e0`；第一轮只写 3 段 → 68/96，补第 4 段后一次命中（t532）。与 §6 联动：一个符号里 N 段 thin wrapper 就写 N 个函数。
- **边界（尾调判定墙，别硬写）**：0x0020FA10 / 0x0020FA20 / 0x0020FA30（各 16 B）的 ROM 只有 **4 条**：`a1 = a0; a0 = 0xB0001000/0xB0001010/0xB0001020; j FUN_0020f9a0`（纯尾调、无帧）。
  - 写 `int f(int a0) { return FUN_0020f9a0(0xB0001000, a0); }`（也试过 void 版）得到 **32/16**：ee-gcc 坚持 `jal` + 建帧，不做 sibcall。
  - [推测] 与实参含大常量（需 `lui+ori` 两条构造）有关 → 属**尾调判定墙**；见到「纯尾调无帧 + 大常量实参」就别写。
- **族成绩**：今天累计 **20/23（87%）** —— 全库命中率最高的一类，优先级不低于 §24 空桩池。

### §26 6 参骨架（今天 5/6 一次过）[证据]

- **形态**：目标帧 **0x40**、保存 **$s0–$s5 + ra**；`jal` 前有 6 条寄存器搬运；**两次调用都全量转发 6 个参数**；末条无参尾调（`j`）。
- **C（照抄，只换 callee）**：

      int f(char *a0, int a1, int a2, int a3, int t0, int t1)
      {
          int r;
          FUN_001af7d0(a0, a1, a2, a3, t0, t1);   /* 第一次：全量转发 */
          r = MID(a0, a1, a2, a3, t0, t1);        /* 第二次：全量转发，结果落 r */
          FUN_001af7e8();                         /* 末条无参 → 自动尾调 j */
          return r;
      }

- **证据**（t575，5/6 一次过）：0x001AC988（MID→FUN_001aca10）、0x001ACC40（→FUN_001accc8）、0x001ACD18（→FUN_001acda0）、0x001ACDE0（→FUN_001ace68）、0x001ACEB8（→FUN_001acf40）—— **五只全部一次过**；MID 一律按 `jal` 立即数精确换算。
- **跳过**：第 6 只 0x001E8AB0 含 **movn**（0x001E8AC4）→ 按 §20 直接跳过。
- **与 §9 的分工**：§9 是「7 参走 `$t0–$t3` + 局部 `char buf[16]`」；本条是「6 参全走 **`$s0–$s5`（callee-saved，跨两次调用保活）**」。判据：看 `jal` 前搬运的目标寄存器是 **s0–s5** 还是 **t0–t3**。

### §27 wrapper 阶梯（一个符号挂多段）[证据]

- **形态**：一段连续地址里**每 24 字节**一段：`addiu sp,-0x10; sd ra,0(sp); ld ra,0(sp); j FUN; addiu sp,0x10`，且 callee 集中在一个区间（C++ vtable 胶水层的典型长相）。
- **C**：每段一个函数，**全部写进同一个 .c**；`jr ra; nop`（8 字节）= 空叶子函数：

      void FUN_001b2838(void) { FUN_001c7690(); }
      void FUN_001b2850(void) { FUN_001c7728(); }
      /* …共 6 段… */
      void FUN_001b28e0(void) { }        /* jr ra; nop —— 空函数 */

- **证据**：0x001B2500–0x001B2900 整段 **20/20 符号全 MATCH（段内 31 只 wrapper）**（t562）—— 含一个符号 **6 段**（0x001B2838，140 B：0x001B2838/2850/2868/2880/2898/28B0 → 0x001C7690/1C7728/1C7758/1C7788/1C77C0/1C77F0）与 **3 段**（0x001B28C8，40 B：1 wrapper + 2 个空叶子）。
- **同类样本**（仍在 t568 的 ≤160B 未匹配名单里，可直接按本节做）：0x001B6060（六 thunk）、0x001B9118（+ 6 个空桩）。
- **坑 1（必读）**：wrapper 生成器/JSON 里的 code **只覆盖首段 20 字节** —— core 更大的符号必须补后续段（0x001B2838 先只写首段就是 20/140，t553 未过）。
- **坑 2**：**core > 100 的多是「thunk + 大函数」混合**，先跳过（t553 的 0x001B2838、t568 归的 complex 类）。
- **批量法**：找那种「每 24 字节一个 `ld ra; j`」的连续段 → 机械生成；optimizer 的 `scan_wrappers.py` 已能按 unarg/arg/complex 三类直接出 C 文本（t568）。

### §28 gp 相对访问的两个坑（+ 一条派单判据） [证据]

#### 1) -G8 判据：ROM 出现 `sw/lw -xxx($gp)` 就说明该 TU 是 -G8 编的

- **现象**：wrapper/小函数里，ROM 的全局写是 gp 相对（`sw v1,-0x6D9C(gp)`），我们出 `lui vN,%hi(D_x) + sw vN,%lo(D_x)` 的绝对两段形态 —— 差几词且改源码无解。
- **做法**：在 **build/flag-overrides.json** 给该地址加 flag：

      { "0x0010C1F0": ["-G8"] }        /* queue 的 g 可能就写着 ["0"]，别照抄 queue */

- **证据**：0x0010C1F0（40 B 区间：wrapper + 第二只 setter `D_00270C54 = 3; return 1`）—— 加 `-G8` 前一直是 `lui+sw` 绝对形态、MISS；加后**一次命中**（t573）。
- **一行判据**：**只要 ROM 里出现 `sw/lw -xxx($gp)`，就先给该地址加 `-G8`，再谈源码** —— 光改源码永远对不上。

#### 2) gp 符号墙：`off($gp)` 在 config/symbols.csv 里没有条目 → 声明什么符号都白搭

- **现象**：长度完全一致（80/80），**4 个词差全部落在 `lw X,off($gp)` 的偏移上** —— 我们 -0xE734，ROM -0x6D44。
- **根因**：声明的符号名（如 `D_008092BC`）在链接层没有被解析到真实的 gp 符号上；`%gp_rel` 的偏移由 symbols 表决定，C 源码无法指定。
- **做法（派单前必查）**：把 ROM 里 `lw X,off($gp)` 的 **off** 拿去 **config/symbols.csv** 查有无对应条目：
  - 有 → 按该符号名声明（再走 §12/§23）；
  - **没有 → 直接跳过这个地址**，别浪费 check-one（属 `%gp_rel` 链接层墙，加 flag 也救不了）。
- **证据**：0x0012D280 / 0x0012D680（t592，80/80、各 4 词，全部卡在 gp 偏移）；同批 45 个「结构初始化」候选抽样全是 `lw v1,-0x6D44($gp)` + `lui at` + `sb/sw at+v1` 形态 → 新写池里这一类**先看 gp 符号覆盖率再派**。
- **相对避风港**：不依赖 gp 符号的 shape —— 「多调用」「守卫回调」「简单叶子」（t592 统计 41+31+5 只）更适合作为下一批。

#### 3) 附带判据（optimizer 纠偏）：**core 不能用来判断真假 wrapper**

- **现象**：直觉上「core 小 = 真 wrapper」，实测**反着来**：
  - 已 matched 的 3 只 wrapper：core = **84 / 72 / 44**；
  - 经验证为假的两只：core = **40 / 64**。
- **根因**：真 wrapper 靠「一个 .c 覆盖多个符号」（多函数 TU），符号区间里本来就含**其它函数的代码**，所以 core 反而更大。
- **正确判据**：`--require-tail-nop` —— wrapper 那条 `j` 之后到符号末尾**必须全是 nop（或下一个 glabel）**；加上该条件后 qualified=0，恰好精确剔除那两只假 wrapper（t583）。
- **补充口径**（t574）：queue 的 core 对真 wrapper 也常在 40–64 B（对齐 padding + 尾部 nop），所以「core ≤ 24」这种筛法在未匹配里会得到 **0 只**；建议用「core≤96 且 wrapper 前缀≤24 B」双门槛。
- **一行判据**：**判 wrapper 真假看「j 之后是不是全 nop」，不看 core 大小。**

- **一句话 checklist（派 wrapper 批前）**：① ROM 有 `-xxx($gp)` → 先加 `-G8`；② `off` 在 symbols.csv 无条目 → 跳过；③ 判真假用 tail-nop，不用 core。
