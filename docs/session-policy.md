# 会话切换规则（硬标准）

> 目的：不再靠“感觉”决定换不换会话。以下四条，满足其一就换，不满足就不换。

## 1. 一阶段一会话

- **阶段** = `docs/STATE.json` 里 `phase` 的取值（M0-spike / M1-build / M2-automation / M2.2-batch / M2.3-llm / ...）。
- **规则**：一个会话只做当前 `phase` 的工作。`phase` 变了，会话结束。
- **不换**：同一 phase 内的连续迭代（跑 50 个、再跑 89 个、改生成器），不拆。

## 2. 阶段完成 = gate 通过

- 完成定义：该阶段在 `STATE.json` 的 `gates` 里有 `status: "passed"`，且 `verified_by` 指向一条可重跑的命令。
- 没到 passed 就换会话 = 违规，下一会话从 HANDOFF 续跑。

## 3. 换会话前必须做两件事

1. 更新 `docs/HANDOFF.md` 顶部「当前进度」：阶段、上次完成、下一步命令。
2. 跑一次 `make progress`（报告 + 看板 + ByteMatch 上传），确保产物与状态一致。

两件都做完才允许换；没做完不许换。

## 4. 上下文占用 > 70% 强制换

- 测量位置：DSH Web GUI 的上下文用量显示（或会话 token 计数）。
- 阈值：**> 70%** 立即换，不管阶段是否完成。
- 换之前照第 3 条执行。

## 不使用的标准（已废止）

- “感觉它开始忘事了”——主观，不作数。
- “做了两个阶段就换”——机械，不作数。
- “任务还没完所以不换”——与第 4 条冲突，以第 4 条为准。
